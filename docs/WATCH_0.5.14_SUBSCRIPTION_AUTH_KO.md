# Watch 0.5.14 — 폰 버튼으로 백그라운드 인증 시작

**한국어** · [English](WATCH_0.5.14_SUBSCRIPTION_AUTH_EN.md)

브랜치: `fix/watch-background-reconnect`. Android **0.6.9-local / 설치 코드 28**은 유지하고 Watch **0.5.14 / 빌드 40**에만 이번 연결 수정을 적용합니다.

## 문제와 변경

원본 0.5.12로 복원한 뒤에도 잠긴 워치에서 폰의 **워치 연결 / 연결 새로고침**만 누르면 구독 후 `awaitingBootstrap` 상태에서 연결 종료가 반복됐습니다. 워치 앱을 열면 인증됐습니다. 폰 재부팅은 성공·실패 사이에 있었으나 직접 원인으로 확정하지 않습니다.

기존 코드는 백그라운드 구독 완료 콜백에서 인증을 즉시 시작하지 않고, 폰의 다음 시작 신호 또는 2초 뒤 앱 타이머를 기다렸습니다. 현재 실패 기록에서는 그 기다림이 끝나기 전에 연결이 종료됐습니다.

- 구독 완료 콜백 안에서 바로 첫 인증 쓰기를 제출합니다. 전면 진입·다음 시작 신호·2초 타이머에 인증 시작을 맡기지 않습니다.
- 중복 구독 콜백이나 늦게 온 최초 시작 신호는 이미 진행 중인 인증의 nonce를 새로 만들지 않습니다.
- 복원된 연결이 `.connecting` 상태라서 재접속 함수가 반환하더라도, Bluetooth가 준비됐을 때 기존 상대 검색을 시스템에 등록합니다. 복원 콜백의 지연 타이머만 기다리지 않습니다.
- 시스템에 이미 복원된 검색이 있으면 앱의 복구 검색 표시도 복원해 해당 검색 결과를 기존 상대 복구로 처리합니다.
- 이전 경로에서 `awaitingBootstrap`이 남은 경우 실행 기회가 주어진 재접속 처리에서도 인증을 재개합니다.

기존 상대 키 확인·암호화 인증·명시적 연결 중지 동작은 유지합니다. 등록·키·차량 버튼 설정을 삭제하거나 재등록하지 않습니다. 앱을 자동으로 화면 앞에 띄우는 기능이 아니라 백그라운드 Bluetooth 콜백에서 처리합니다. 알림 레이아웃과 차량 명령은 변경하지 않습니다.

## 적용 상태

- 실제 워치용 서명 빌드 완료.
- 기기 설치 진행 중. 잠긴 워치의 폰 버튼 단독 연결 성공으로 완료 표시하지 않습니다.
- 폰 APK 교체는 필요하지 않습니다. 현재 폰 0.6.9를 그대로 사용합니다.
- 시스템 로그 수집·차량 제어 실행·추가 재부팅·거리 이동은 수행하지 않습니다.

이전 원본 복원 기록은 [0.5.12 복원 문서](ROLLBACK_0.5.12_KO.md)에 남깁니다. 원본 코드 그대로의 복원과 이번 동작 변경을 구분합니다.
