# FoldBridge Local 구조

현재 구성은 Galaxy Z Fold 계열 Android 휴대폰의 알림을 Apple Watch에 BLE로 직접 전달하는 Android 앱과 watchOS 앱이다. 알림 전달 자체에 서버·인터넷·페어링된 아이폰을 사용하지 않는다. 초기 워치 설정과 개발용 서명/설치에는 Apple 개발 도구와 기기 등록 절차가 필요하다.

## 데이터 흐름

1. `NotificationRelay`가 Android 알림 접근 서비스로 다른 앱의 알림을 받는다.
2. 제목·본문·앱 표시명·원본 앱 아이콘과 알림 ID/내용 리비전을 만들고 `BridgeService`의 미전달 목록에 넣는다.
3. 갤럭시는 BLE GATT peripheral/server, 워치는 central/client로 연결한다.
4. 양쪽에서 처음 비교한 키를 고정하고, 연결마다 새 세션 키를 파생해 메시지를 암호화한다.
5. 워치 `WatchLink`가 메시지를 조립·복호화하고 로컬 알림 표시 권한을 확인한다.
6. watchOS에 알림 등록을 요청하고 성공하면 수신 확인을 보낸다. 이 확인은 표시 요청 수락 또는 이미 아는 리비전이라는 의미이며 사용자의 열람 확인은 아니다.
7. 휴대폰은 확인된 리비전을 미전달 목록에서 제거한다. 끊김 후에는 남아 있는 알림을 동기화한다.

## Android 실행

`BridgeService`는 `connectedDevice` foreground service로 실행된다. Bluetooth 권한과 다른 앱의 알림 접근은 별도다. Android의 일반 알림 권한은 앱 자체 알림 표시 권한이며 다른 앱의 알림을 읽는 권한이 아니다.

연결 시작 설정을 켜 둔 경우 `BOOT_COMPLETED`(첫 잠금 해제 후), `MY_PACKAGE_REPLACED`, Bluetooth 켜짐 때 서비스를 재개한다. 알림 수집 서비스가 다시 연결된 경우에도 재개를 요청한다. 이미 실행 중이면 기존 서비스를 사용한다. BLE 서버/서비스/광고 준비 실패는 1초부터 최대 30초 간격까지 지연을 늘리며 재시도한다. Bluetooth가 꺼진 동안은 재시도를 멈추고 켜짐 이벤트에서 재개한다. 업데이트 뒤 앱을 열어도 연결 시작 설정에 따라 서비스를 재개한다. 사용자가 연결 중지를 누르면 자동 시작 설정을 끈다. 강제 종료와 OS 실행 제한을 무시하지 않는다.

## 필터와 보관

모든 앱 전달이 기본이며 선택 앱만 전달하도록 바꿀 수 있다. 자체 연결 상태 알림은 제외한다. Samsung System UI의 충전 상태(`charging_state`, 또는 ongoing 시스템 알림인 `CHR` 채널)는 기본 제외한다. 이 항목은 충전율 변화마다 갱신되어 반복 알림을 일으켰으며 `충전 상태 알림 전달` 설정으로 다시 포함할 수 있다. 다른 중요 시스템 알림을 일괄 차단하지 않는다.

미전달 목록은 암호화해 최대 24시간/1,024개 저장한다. 같은 Android 알림 ID의 수정본은 최신 내용으로 대체한다. Android가 숨긴 본문은 복원하지 않는다. 한도 초과 시 오래된 항목부터 제거한다.

## 워치 실행과 위치 연결 유지

위치 연결 유지는 사용자가 켜는 실험 기능이다. 백그라운드 위치 업데이트를 요청해 실행 시간을 얻고, 위치 이벤트와 실행 중인 30초 타이머에서 연결/미전달 동기화를 시도한다. 좌표는 검사·저장·전송하지 않고 콜백 시각만 표시한다. 타이머가 앱을 깨우거나 알림을 생성하지는 않는다.

위치 세션과 BLE 연결이 모든 알림의 무제한·즉시 백그라운드 수신을 보장하지 않는다. watchOS는 앱을 중단/종료할 수 있다. 운동·오디오 세션과 루팅을 사용하지 않는다. APNs를 통한 깨우기는 현재 Local 경로에 없다.

## 로컬 데이터

Android 개인 키는 Android Keystore, 워치 개인 키는 기기 전용 Keychain에 둔다. 휴대폰에는 수신 확인 전 미전달 목록만 저장한다. 워치는 알림 내용의 별도 수신함을 두지 않으며 중복 방지용 ID/리비전 해시 512개만 저장한다. 빌드 6 첫 실행에서 이전 inbox의 해시만 옮긴 뒤 제목·본문을 포함한 기존 inbox를 제거한다. watchOS 알림 센터의 알림은 유지한다. 양쪽 `foldbridge-status.json`은 연결/권한/단계별 개수만 기록하며 알림 본문·개인 키·위치 좌표는 넣지 않는다.

워치 앱의 기존 FoldBridge와 Local 프로필은 휴대폰 키/식별자를 따로 보관한다. 기존 앱과 Local Android BLE 서비스를 동시에 실행하지 않는다. 읽음·삭제의 양방향 동기화는 구현하지 않았으며 알림 열람/삭제는 watchOS 알림 센터에서 처리한다.

## 보존한 초기 구성

`relay/`의 APNs 중계, `windows/`의 Windows 도구, `legacy/`의 초기 문서/테스트 소스는 이력 보존용이다. 현재 Android Local manifest에는 INTERNET 권한이 없고 실행 중계 경로도 사용하지 않는다.

## 원본 앱 아이콘과 알림 UI

Android `AppIcons`는 PackageManager의 원본 앱 아이콘을 읽고 BLE 메시지 크기에 맞춰 48px부터 단계적으로 축소한 PNG로 만든다. PNG는 최대 3,072바이트이며 SHA-256 키로 식별한다. 같은 연결에서 해당 아이콘을 포함한 알림의 ACK를 받으면 이후에는 아이콘 키만 보낸다. 아이콘과 알림 본문은 함께 암호화된다.

워치는 아이콘을 Application Support 폴더에 저장하고 메모리 캐시를 사용한다. 이미지 첨부는 만들지 않는다. 팝업과 카드는 시스템 표시이며, 원본 아이콘이 있는 알림의 펼친 본문만 24pt 아이콘을 포함한 제한 폭 SwiftUI 화면을 사용한다. 아이콘이 없으면 시스템 텍스트 화면을 사용한다. 발신 앱 ID로 알림을 묶는다. 새 아이콘이 기존 수신 알림에 추가돼도 같은 내용 리비전을 다시 알리지 않는다.

watchOS의 short-look과 상단 sash는 시스템이 FoldBridge 앱 이름/아이콘으로 생성한다. 이는 원본 Android 앱의 알림으로 바꿀 수 없으며 원본 아이콘은 사용자 정의 콘텐츠 영역에 표시한다. [Apple 문서](https://developer.apple.com/documentation/watchos-apps/presenting-notifications-on-apple-watch)

기존 암호화/프레임 형식을 유지하며 추가 아이콘 필드는 선택 사항이다. 아이콘이 없거나 원본을 가져올 수 없으면 기본 앱 심벌을 표시한다.

## 재시작 후 등록 유지와 재연결

양쪽의 개인 키와 등록 상대 공개 키는 재시작으로 삭제하지 않는다. 앱 프로세스/세션 복원 시 이전 암호화 세션은 재사용하지 않고 저장된 상대 키를 확인해 새로운 세션을 만든다. 저장된 기기 조회가 실패하면 서비스 UUID로 다시 찾는다. 기존 주소의 연결이 20초 동안 대기 중인 경우에도 보조 검색을 수행해 갤럭시 재시작에 따른 주소 변화를 처리한다. 새로 발견한 상대도 공개 키가 일치해야 수신이 가능하다.

워치는 앱 시작 시 저장된 연결을 재개하고, Core Bluetooth 복원 콜백에서 연결/연결 중/연결 해제 상태를 처리한다. 등록된 휴대폰이 있으면 30분 뒤 백그라운드 갱신을 요청하고, 갱신을 받으면 다음 갱신과 재연결을 요청한다. 이 요청은 watchOS의 실행 기회를 이용하며 부팅 자동 실행이나 30분 주기를 보장하지 않는다. 잠금 해제 전 키 접근, 앱 강제 종료, OS 실행 예산 때문에 앱을 직접 열어야 할 수 있다. 위치 세션은 허용된 전면 실행에서만 재개한다. [Apple 백그라운드 작업](https://developer.apple.com/documentation/watchkit/using-background-tasks)

## 연결 새로고침

갤럭시 메인의 연결 새로고침은 기존 GATT 서버·광고·인증 세션을 닫고, 0.5초 뒤 새 서버와 광고를 준비한다. 서버 세대를 증가시켜 이전 서버에서 늦게 온 콜백을 무시한다. 등록 키와 미전달 대기열은 삭제하지 않는다. 동일 연결 콜백은 중복 처리하지 않고, DISCONNECTED에서만 세션을 정리하며 인증이 성공하면 이전 오류를 지운다.

워치 새로고침은 기존 연결 취소 후 다시 검색한다. 취소 완료 콜백 또는 대기 후 검색으로 진행하고, 이전 연결의 콜백과 인증 시작 메시지가 새 세션을 중복 시작하지 않도록 한다. 상대 키 확인은 그대로 수행한다. 동기화 버튼은 정상 인증된 세션의 미전달 알림을 요청하는 기능이므로 새로고침과 구분한다.

## 기본 알림 상세 화면 복원 (Watch 0.4.1)

초기 버전은 UNNotificationContent의 title/subtitle/body를 시스템이 배치했다. 원본 아이콘 추가 이후 WKNotificationScene의 사용자 정의 SwiftUI 화면을 사용하면서 펼친 알림에서 크기/배치 문제가 반복됐다. 간격 조정으로 해결하지 않고 해당 scene과 hosting controller/view 자체를 제거했다. 새 알림 카테고리는 FOLDBRIDGE_NATIVE_ALERT이며 UI는 watchOS가 그린다.

원본 아이콘은 UNNotificationAttachment를 이용한다. 캐시 PNG를 고유한 임시 폴더로 복사하고 첨부하므로 시스템의 첨부 파일 이동으로 캐시가 사라지지 않는다. 첨부 등록 실패 시 텍스트만 다시 등록한다. 이전 알림을 삭제하거나 다시 울리게 하지 않으며, 등록·언어 선택·BLE 통신은 유지한다.

## 미디어 첨부 제거 (Watch 0.4.2)

0.4.1의 첨부는 앱 아이콘이 아닌 미디어이므로 시스템이 크게 표시하거나 그룹/개별 카드의 썸네일로 재사용할 수 있었다. 원본 PNG 크기와 시스템 미디어 영역 크기는 별개다. 0.4.2는 이 첨부 경로 전체를 제거한다. 기본 알림에는 FoldBridge 시스템 아이콘과 원본 앱 이름/제목/본문만 표시한다. 이전 알림의 첨부를 삭제하거나 다시 등록하지 않으므로 새로 수신하는 알림부터 적용된다. 기본 시스템 아이콘을 그룹과 개별 카드에서 각각 바꾸는 공개 API는 사용하지 않는다.

## 작은 원본 아이콘을 상세 본문에 표시 (Watch 0.4.3)

사용자가 원본 아이콘을 유지하는 두 번째 표시 방식을 선택했다. `FOLDBRIDGE_COMPACT_ICON_ALERT`만 CompactNotificationController/CompactNotificationView에 연결한다. 기존 native 카테고리와는 분리하며 원본 아이콘이 캐시에 있을 때만 선택한다.

notification host의 intrinsic size를 제한하기 위해 화면 폭에서 40pt를 뺀 유한 폭을 모든 행과 텍스트에 지정한다. icon은 24×24pt, 간격은 8pt이며 나머지 폭에 앱 이름을 배치한다. 본문 높이와 줄 수를 고정하지 않는다. GeometryReader, maxWidth infinity, Spacer, 중첩 ScrollView, 추가 scene padding을 사용하지 않는다. 이미지가 미디어 미리보기로 승격되지 않도록 UNNotificationAttachment는 사용하지 않는다. 첫 팝업/카드/sash는 시스템 FoldBridge 표시를 유지한다.

## 상세 본문의 기본 간격에 맞춘 조정 (Watch 0.4.4)

원본 아이콘은 오른쪽 24pt로 유지한다. 유한 본문 폭을 screenBounds.width-32로 넓혀 좌우 기준 여백을 16pt로 맞추고, VStack 문단 간격은 2pt로 줄인다. 추가 vertical padding 4pt를 제거해 제목·본문의 시작 위치를 위로 옮긴다. 제목·발신자·본문의 왼쪽 기준선과 시스템 글꼴은 유지한다. 이 값은 FoldBridge가 선택한 배치이며 Apple 시스템 알림의 비공개 치수와 동일하다고 주장하지 않는다.
