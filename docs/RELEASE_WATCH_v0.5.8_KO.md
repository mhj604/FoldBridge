# Watch 0.5.8 · 빌드 32 / Android 0.6.4

**한국어** · [English](RELEASE_WATCH_v0.5.8_EN.md) · [전체 사용 안내](RELEASE_WATCH_v0.5.7_KO.md)

## 백그라운드 연결 조사

앱 화면을 열어야만 연결하도록 만든 구조는 아닙니다. 저장한 기기로 연결을 요청하고, OS 자동 재연결·서비스 UUID 검색·상태 복원을 사용합니다. watchOS는 백그라운드 실행과 BLE 수신 기회를 제한하므로 항상 즉시 연결되는 것은 아닙니다.

2026-11-06 기기 기록에서 앱이 백그라운드인 상태의 연결 성공과 빠른 연결 종료·재시도가 함께 관찰됐습니다. 갤럭시 기록에는 상대 기기에서 연결을 종료한 것으로 나왔으나, 기존 워치 기록만으로 앱의 취소 호출과 시스템 동작을 구분할 수 없었습니다. 오류 코드가 없다는 이유로 사용자가 수동 해제했다고 해석하면 안 됩니다.

이 버전은 원인 구분을 위한 진단 변경입니다. **끊김 원인을 확정하거나 영구 해결한 버전으로 표시하지 않습니다.** 설치 후 읽은 기록에는 백그라운드 인증 성공이 있었으나, 업데이트 직후 결과가 장기간 자동 연결을 입증하지는 않습니다.

## 추가된 기록

- 앱에서 연결 취소를 요청한 횟수와 이유: `cancellationCount`, `lastCancellation`
- 연결 종료 오류의 도메인·코드·설명: `lastDisconnect`
- 연결 완료·종료 콜백이 현재 관리 중인 기기의 객체인지 여부
- 앱의 연결 취소 이벤트 `cancel.*`와 일반 연결 종료 이벤트 `disconnect.ended.*` 구분

기록은 워치 앱 컨테이너의 `Documents/foldbridge-status.json`, `Documents/foldbridge-events.json`에 보관합니다. 이벤트는 최근 128개로 제한하며, 이 변경에서 메시지 본문·차량 인증 정보는 기록하지 않습니다. 실제 차량 명령은 진단을 위해 실행하지 않습니다.

Android는 0.6.4를 그대로 사용합니다. 알림 배치·차량 제어·등록 키와 버튼 설정은 이 변경의 대상이 아닙니다. [빌드와 설치](BUILD_AND_SETUP.md)

Apple의 [백그라운드 BLE 설명](https://developer.apple.com/videos/play/wwdc2022/10135/)에는 연결 유지·범위 복귀 시 재연결과 수신 예산 제한이 함께 설명돼 있습니다. 소개 당시 watchOS 9의 구체적인 횟수를 최신 OS의 고정 한도로 단정하지 않습니다.
