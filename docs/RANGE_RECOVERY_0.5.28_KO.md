# Watch 0.5.28 — 잠금 중 복구 콜백과 거리 복귀

**한국어** · [English](RANGE_RECOVERY_0.5.28_EN.md) · [현재 상태](CURRENT_STATUS_KO.md)

2026-11-18. 워치 앱·위젯 **0.5.28 / 빌드 62**, Android **0.6.20 / 코드 42**. 기존 등록·키·UUID·위치 활동·화면 정책을 유지합니다. 화면 자동 표시 문제는 실사용 관찰을 기다리며 보류합니다.

## 관측과 원인 범위

REA로 현재 양쪽 앱 기록을 읽었습니다. 수정 전 워치는 실제 백그라운드·인증·읽기 수신 상태였고 취소/실패 기록이 없었습니다. 폰도 인증 링크·수신 준비 상태이며 실제 native 종료와 10초 이상 읽기 재개 카운터는 0이었습니다. 이 시점의 근거리 동작을 모든 장시간 잠금·거리 복귀의 성공으로 확대하지 않습니다.

앞선 REA 이벤트에는 17:30:05 거리 시간 초과 뒤 17:31:02 대기 연결 취소, 17:31:26 휴대폰 광고, 17:31:27~28 인증·읽기 복구가 남아 있습니다. 광고를 관측하기 전에 시간 경과만으로 연결 대기를 취소하던 경로가 있었습니다. 이것만으로 당시 정확한 물리 복귀 시각이나 watchOS 내부 사유를 알 수는 없습니다.

소스에서는 다음 복구 공백을 찾았습니다.

- 대기 연결을 교체할 때 현재 주변 기기를 비우고 취소를 요청합니다. 종료 콜백은 교체를 마무리했지만, 연결 실패 콜백은 비워진 현재 기기 검사에서 반환해 3초 후 앱 타이머만 남길 수 있었습니다.
- 검색에서 같은 휴대폰을 발견해도 기존 상태가 `connecting`이면 바로 반환했습니다. 잠금 중 그 검색 콜백이 유일한 실행 기회인 경우 다음 위치/유지 타이머까지 복구가 미뤄졌습니다.
- 복구 구간에서 재요청 한 번이 실패하면 재인증될 때까지 다시 복구할 수 없는 조건이 있었습니다.

이는 코드상 공백과 관측된 대기 패턴을 함께 다룬 수정이며, 현재 기기에서 모든 장애 원인이 확정됐다는 뜻은 아닙니다.

## 수정

1. 연결 실패·종료 콜백 양쪽에서 취소한 상대의 UUID를 확인하고 교체를 마칩니다. 해당 콜백 안에서 다음 네이티브 요청을 제출해 앱 타이머 의존을 줄입니다. 지연 콜백 누락을 위한 기존 3초 fallback은 유지합니다.
2. 실제 거리 복구가 필요하고 45초 이상 `connecting`에 머물렀으며 **현재 대기 요청 이후 휴대폰 광고를 발견한 경우에만** 멈춘 요청을 재설정합니다. 정상 인증/물리 연결에는 적용하지 않습니다. 광고를 못 본 채 시간만 흘렀다는 이유로 취소하지 않습니다.
3. 같은 휴대폰 광고 콜백에서도 즉시 복구를 처리합니다. 백그라운드에서 광고 중복이 합쳐져도 첫 발견 기록을 사용하므로 짧은 시간 안에 두 번째 광고를 요구하지 않습니다.
4. 실패 뒤의 재설정은 새 대기 요청 이후 광고 증거가 있고 60초 간격 조건을 만족할 때만 다시 허용합니다. 성공한 인증 뒤에는 복구 상태를 비워 다음 거리 이탈도 처리합니다.
5. Core Bluetooth 복원 기회를 받으면 저장 연결뿐 아니라 멈춘 단계 복구도 요청합니다. 복구 완료 콜백 종류와 광고 나이를 앱 상태에 구분해 기록합니다.

OS가 정지된 앱의 타이머를 실행하게 만드는 기능은 아닙니다. 네이티브 연결·서비스 필터 검색을 남기고 실제 콜백/실행 기회가 왔을 때 복구를 진행하는 변경입니다. 위치·알림 전송 방식·차량 명령·이전 알림 배제 규칙은 바꾸지 않습니다.
