# 버튼 없는 재연결: 현재 수정과 남은 조건

**한국어** · [English](AUTO_RECONNECT_EN.md)

목표는 워치 잠금을 푼 뒤 폰이나 워치에서 새로고침을 누르거나 워치 FoldBridge를 열지 않아도 연결되는 것입니다. 현재 버전은 Android **0.6.7 / 코드 23**, Watch **0.5.8 / 빌드 32**입니다.

## Android 0.6.7-local · 코드 23 (Watch 0.5.8 유지)

Android의 GATT 서버 연결 콜백에는 다른 BLE 통신으로 생긴 연결도 들어올 수 있습니다. 이전 코드는 첫 물리 연결을 워치로 선택하고 광고를 중단해, 다른 기기가 연결 대기를 점유할 수 있었습니다. 이제 FoldBridge TX 특성의 CCC 구독을 요청한 기기만 선택합니다. 상대 키를 검증하는 기존 암호화 인증은 그대로 적용합니다. MTU는 기기별로 보관해 구독 시점에 적용하며, 다른 기기의 연결·해제로 워치 세션을 초기화하거나 그 기기의 연결을 취소하지 않습니다.

실행 중인 폰 서비스는 15초 간격으로 폰 Bluetooth 스택의 연결 상태를 확인합니다. 실제 연결이 사라졌는데 앱 상태만 남으면 정리하고 광고를 다시 시작합니다. 이 확인은 워치에 주기적인 heartbeat를 보내지 않습니다. 진단에 광고 상태, 물리 연결 콜백 횟수, 실제 구독 선택 횟수, 로컬 상태 확인 시간을 추가합니다.

기기에서 APK 업데이트 뒤 새로고침 없이 인증된 상태와, 폰 프로세스를 종료하고 폰 앱만 다시 실행한 뒤 새로고침 없이 인증된 상태를 각각 읽었습니다. 에이전트는 이 과정에서 워치 FoldBridge를 실행하지 않았습니다. Mac–워치 개발 터널이 연결되지 않아 워치 화면 및 잠금·해제 사이클은 직접 확인하지 못했습니다. 따라서 모든 잠금 해제·장시간 대기에서 자동 연결이 해결됐다고 주장하지 않습니다. [범위와 남은 조사](AUTO_RECONNECT_KO.md)

## 워치 쪽에서 구분할 사항

- 저장된 상대 연결·서비스 필터 검색·Core Bluetooth 복원 경로는 이미 구현돼 있습니다.
- 위치 기반 연결 유지 세션을 새로 시작하는 경로는 앱 활성 상태에 한정돼 있습니다. 워치 잠금 해제와 앱 활성화는 다른 동작입니다.
- 멈춘 인증의 시간 초과 복구 일부는 전면 상태에 한정돼 있습니다. 현재 장애가 이 지점인지 워치 기록을 읽어야 구분할 수 있습니다.
- 백그라운드 BLE 수신 및 실행 예산은 watchOS가 관리합니다. [Apple 설명](https://developer.apple.com/videos/play/wwdc2022/10135/). 과거 watchOS 9의 구체적인 횟수를 현재 OS의 고정 한도로 간주하지 않습니다.

현재 수정과 별개로 Mac–워치 개발용 연결이 필요합니다. 이것은 평소 갤럭시–워치 BLE 사용 경로에 Mac이 필요하다는 뜻이 아닙니다. 이번 작업에서 차량 명령, 워치 등록 초기화, 서명 자동 갱신 일정 변경은 수행하지 않았습니다.
