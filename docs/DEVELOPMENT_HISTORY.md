# 구축 이력과 문제 해결

## 요구사항

- Galaxy와 Apple Watch만으로 BLE/로컬 알림 전달.
- 앱 사용 중 서버·인터넷·페어링된 아이폰 의존 제거.
- 무료 Apple 개발 Team 사용.
- 루팅과 운동/오디오 세션을 통한 연결 유지 제외.
- 화면 꺼짐/다른 앱 사용 중 수신을 가능한 범위에서 유지하되 watchOS 제한을 명시.

## 초기 구성

초기 0.1.0 패키지의 Android·watchOS·Windows·APNs 중계 소스를 기반으로 워치 Xcode 빌드와 개발 기기 설치를 진행했다. watch-only 관련 Info 설정 충돌을 정리했다. 계정 로그인, 기기 개발자 모드, Mac–Watch 개발 페어링, 코드 서명을 완료해 실제 워치에 설치했다.

원래 Android 앱의 서명 키가 없어 기존 앱을 삭제하지 않고 새 `dev.foldbridge.local` 앱을 별도로 만들었다. 새 Local 서명 키를 만들고 후속 업데이트에 재사용했다. 워치에는 기존/Local 프로필을 추가해 각 휴대폰 키와 식별자를 분리 보관했다.

## Local 0.2.0 / 워치 build 3

- Local GATT UUID를 별도 사용.
- Android INTERNET 권한과 실행 중계 경로 제거.
- 모든 앱 전달 기본값, 알림 종류의 일괄 필터 제거.
- indication 및 앱 ACK, 순차 전송과 재연결/재전송.
- 미전달 보관 24시간/1,024개.
- 위치 기반 연결 유지 및 실행 중 30초 동기화.
- 기존 서비스와 Local 서비스 간섭을 피하도록 기존 앱 연결 중지 안내.

## Local 0.2.1 / 워치 build 4 — 알림 미수신

양쪽 앱을 열어도 알림이 오지 않는 증상을 실제 기기에서 분석했다. Bluetooth/일반 알림 권한과 연결 서비스는 살아 있었지만 `enabled_notification_listeners`에 Local 알림 수집 컴포넌트가 없었고 알림 접근 서비스도 연결되지 않았다. **다른 앱의 알림 접근 권한 누락**이 직접 원인이었다.

사용자가 권한을 허용한 뒤 시스템에서 Local 알림 수집 서비스가 연결된 것을 확인했다. REA로 권한 설정·패키지·설치·상태 파일·로그를 수집했다. 이후 Android는 수신 확인 11건/전달 대기 0건, 새 워치 빌드는 수신 및 로컬 알림 등록 2건을 기록했다. 양쪽 숫자는 기존 리비전의 중복 확인과 재전송 때문에 같은 누적값이 아니다.

수정 사항:

- Bluetooth 상태와 알림 접근/수집 서비스 상태를 별도로 표시.
- 권한 누락 시 상세 설정으로 안내, 허용된 서비스의 재바인딩 요청.
- 워치 알림 권한 확인 후 등록/ACK, 전면 배너/목록/소리 표시 요청.
- 워치 백그라운드 작업의 임의 4초 종료 제거.
- 알림 본문을 넣지 않는 단계별 상태 기록 추가.

## Local 0.2.2 / Android build 5 — 반복 충전 알림

사용자가 충전율이 1%씩 오를 때 System UI 알림이 반복된다고 보고했다. 기기 기록에서 `com.android.systemui`, `charging_state` 태그, `CHR` 채널, ongoing/only-alert-once 표시를 가진 충전 상태 알림을 확인했다. 이 알림의 제목/본문 갱신을 새 내용 리비전으로 전달해 워치에서 반복 표시한 것이다. 진단용 테스트 알림을 주기적으로 발송한 것이 아니다. 30초 타이머는 연결/미전달 동기화만 수행한다.

- 충전 상태 알림을 기본 제외하고 선택적으로 다시 포함하는 설정 추가.
- 이미 대기 중인 같은 충전 알림 ID도 제거.
- 다른 앱/중요 시스템 알림을 일괄 차단하지 않음.
- 연결 시작 설정을 켜 둔 경우 업데이트 후 앱을 열면 서비스 재개.
- Gradle 앱 ID와 버전을 현재 Local APK 구성에 맞춤.

워치 BLE 프로토콜 변경이 없어 이 수정은 Android 업데이트만 필요하다.

## 남는 범위

ACK와 로컬 알림 등록 성공은 사용자가 화면을 보거나 알림을 읽었다는 뜻이 아니다. 장시간 백그라운드의 모든 알림 즉시 수신은 입증/보장하지 않는다. 위치 모드도 watchOS의 중단/종료 정책을 무시하지 않는다. 읽음·삭제 양방향 동기화는 포함하지 않는다.

실기기 오류 분석과 빌드/설치 작업을 수행했으며 별도의 테스트 알림이나 테스트 스위트, 자동 CI는 실행하지 않았다. `legacy/tests/`는 초기 소스를 보존한 것이다.

## Local 0.3.0 / 워치 0.2.0 build 5 — 원본 아이콘과 UI

- 갤럭시 PackageManager 원본 앱 아이콘을 크기 제한 PNG로 추출해 알림과 함께 암호화 전달.
- 연결 중 아이콘 ACK를 기준으로 중복 이미지 전송 생략, 워치 파일/메모리 캐시 추가.
- 워치 최근 알림·상세 화면·SwiftUI long-look 본문에 원본 아이콘 표시.
- 원본 앱별 알림 그룹과 기존 알림 기록의 선택적 아이콘 필드 추가.
- watchOS 최초 short-look과 상단 sash의 아이콘/앱 이름을 다른 앱으로 바꿀 수 없다는 범위를 명시.
- 갤럭시 연결 카드/핵심 알림 설정, 워치 최근 알림/상세/별도 설정으로 UI 정리.
- 원래 기본 연결과 위치 모드, 충전 알림 필터, 페어링/수신 기록 유지.
- 자체 FoldBridge 아이콘 및 재생성 스크립트와 리소스 빌드 설정 추가.
- 새 설치는 Local 기본, 기존 프로필 저장값은 유지.

## 민감한 알림 가림과 앱 내 보관 제거 — watchOS 0.2.1 / 빌드 6

- 갤럭시의 Local 앱에서 `RECEIVE_SENSITIVE_NOTIFICATIONS` AppOp가 `ignore`로 설정되어 민감한 본문 수신이 거부되고 있었다. 해당 앱에 `allow`를 적용하고 알림 수집 서비스를 재연결한다. Android APK는 0.3.0을 유지한다.
- 워치의 최근 알림 목록과 상세 화면을 제거하고 연결 상태/알림 센터 안내로 바꾼다.
- 기존 inbox는 제목·본문을 읽어 앱에 복원하지 않고 수신 식별값만 이전한 뒤 삭제한다. 이후에도 알림 내용은 별도로 저장하지 않는다. 알림 센터와 페어링은 유지한다.
- 미수신 알림의 휴대폰 대기열과 수신 확인, 중복 방지 해시, 원본 앱 아이콘 표시를 유지한다.

## 재시작 후 재연결 보완 — Android 0.3.1 / watchOS 0.2.2 빌드 7

- Galaxy: 부팅 외에 APK 교체/알림 수집 서비스 재연결 시에도 저장된 연결 시작 의도를 복원. 실행 중 서비스 재사용, BLE 서버/서비스/광고 초기화 실패 재시도, Bluetooth 끄기/켜기 시 재시도 정리.
- Watch: 앱 시작 시 연결 재개, Core Bluetooth 복원 상태별 처리, 기존 기기 캐시 조회 실패 시 보조 검색, 오래된 주소의 연결이 대기 중일 때 보조 검색. 저장된 상대 공개 키 확인과 매번 새로운 암호화 세션 생성 유지.
- Watch: 등록된 휴대폰에 대해 백그라운드 갱신을 요청해 추가 재연결 기회를 확보. 부팅 자동 실행과 정확한 갱신 주기는 보장하지 않으며, OS가 실행시키지 않으면 잠금 해제 후 앱을 한 번 열어야 할 수 있음.
- 별도 재부팅 시험이나 인위적 테스트 알림은 실행하지 않음.

## 워치 알림 글씨 배치 정리 — watchOS 0.2.3 / 빌드 8

초기 버전은 시스템 기본 알림 레이아웃이었다. 원본 아이콘 추가 때 도입된 40pt 헤더/12pt 문단 간격을 줄이고, 앱 이름·제목·본문의 왼쪽 기준선을 통일했다. 원본 아이콘은 헤더 오른쪽에 24pt(사용자 글자 크기에 따라 조정)로 유지한다. 장문은 고정 높이나 줄 수 제한 없이 시스템 스크롤을 이용한다. 화면별 scene padding을 사용하고, 사용자 정의 상단 색상을 제거해 watchOS 기본 상단을 사용한다. Android와 전송/재연결 방식은 그대로 유지한다.

## 앱 아이콘 중앙 정렬 — Android 0.3.2 / watchOS 0.2.4 빌드 9

아이콘 도형의 선 두께까지 포함한 가로 범위가 원본 1024px 캔버스에서 217.5...755.5여서 중심이 486.5px에 있었다. 생성 코드에서 전체 도형을 오른쪽으로 25.5px 옮겨 캔버스 중심인 512px에 맞췄다. 워치 1024px 아이콘과 Android 256px 아이콘을 같은 수정 원본으로 생성한다.

## 아이콘 시각적 정렬·연결 새로고침·한국어 배포 안내 — Local 0.4.0 / Watch 0.3.0 빌드 10

- 실제 문제 상태는 Android 인증 시간 만료/워치 연결 없음/휴대폰 미전달 4개였다. 기존 동기화 버튼과 별도로 두 앱에 연결 새로고침을 추가했다. 등록·대기열을 보존하며 GATT/세션을 다시 준비한다.
- GATT 서버를 닫은 뒤 도착한 콜백이 새 서버 상태를 바꾸지 않도록 세대를 분리했다. 같은 연결 콜백 중복 처리를 피하고, 연결 해제 상태에만 세션을 정리한다.
- 워치는 중복 구독 콜백에서 인증 시작을 반복하지 않도록 단계를 구분했다. 인증 성공 시 휴대폰의 과거 만료 오류를 지운다.
- 바깥 경계 정렬만으로는 시각적 중심이 왼쪽에 남았다. 밝기·면적 가중 중심으로 아이콘을 다시 그렸고 watchOS asset 이름을 FoldBridgeIcon으로 바꿨다. 등록 데이터를 삭제하는 앱 재설치는 사용하지 않는다.
- 사용자별 정보 대신 일반 설치 순서를 중심으로 README를 다시 구성하고 빠른 시작·문제 해결·기여·변경 이력을 한국어로 작성했다.

## 앱 내 한국어/영어 선택 — Local 0.5.0 / Watch 0.4.0 빌드 11

- 양쪽 설정에 언어 메뉴와 시스템 설정/한국어/English를 추가했다. 두 기기는 언어를 독립적으로 저장한다.
- 공유 영어 카탈로그에서 Android 네이티브 문자열과 워치 번들 리소스를 생성한다. Android는 앱별 LocaleManager 설정을 사용하고, 워치는 선택을 UserDefaults에 저장한다.
- 상태와 오류는 표시할 때 번역해 언어만 바꾸기 위해 인증 세션을 끊지 않도록 했다. Android의 자체 foreground 알림/채널도 구성 변경 시 갱신한다.
- 수신 메시지와 원본 앱 이름은 번역하지 않는다. 페어링 키·미전달 대기열과 위치 연결 유지 설정은 보존한다.

## 알림 상세 화면의 시스템 레이아웃 복원 — Watch 0.4.1 / 빌드 12

사용자는 알림 센터의 첫 카드는 정상이고 누른 뒤 펼친 화면만 깨진다고 구분했다. 이전 여백/헤더 변경은 사용자 정의 화면을 계속 사용했으므로 초기 시스템 배치를 복원한 것이 아니었다. 이번에는 WKNotificationScene, RelayNotificationController, RelayNotificationView를 제거하고 시스템 기본 화면으로 되돌렸다.

원본 아이콘은 캐시 원본과 분리한 임시 복사본을 UNNotificationAttachment로 첨부한다. 첨부 등록 실패 시 텍스트만 재요청하고 최종 성공에 ACK한다. 카테고리를 FOLDBRIDGE_NATIVE_ALERT로 바꾸고 기존 알림은 삭제/재알림하지 않는다. Android 0.5.0과 언어·재연결·보관 정책은 유지한다.

## 앱 그림을 미디어 첨부로 사용하던 처리 제거 — Watch 0.4.2 / 빌드 13

0.4.1의 표준 이미지 첨부가 팝업에서 커지고 그룹/개별 카드 썸네일로 재사용되는 문제가 보고됐다. 앱 그림과 미디어 첨부를 혼용한 방식이었다. UNNotificationAttachment 생성·임시 복사·첨부 실패 재요청 경로를 제거하고 기존 텍스트 알림 등록 경로로 정리했다. 원본 앱 아이콘 캐시는 미디어 첨부와 분리한다. 시스템이 기존 알림에 보관 중인 첨부는 자동 삭제/재발송하지 않는다.
