# Watch 0.5.9 / 빌드 33: 설치 및 백그라운드 복원 기록

**한국어** · [English](WATCH_0.5.9_CANDIDATE_EN.md)

이 브랜치는 Android 0.6.7 수정에 워치의 백그라운드 복원 변경을 추가합니다. 2026-11-07 실제 Apple Watch Ultra 2에 **Watch 0.5.9 / 빌드 33**을 덮어 설치했고, 설치 목록과 앱 자체 진단에서 새 빌드를 확인했습니다. 폰에는 **Android 0.6.7-local / 코드 23**이 설치되어 있습니다. 이 브랜치의 설치 결과와 기본 브랜치의 Watch 0.5.8 안내는 구분합니다.

## 변경

- 백그라운드에서 복원한 TX 알림 구독이 이미 살아 있으면 유지한 채 보안 인증을 시작합니다. 마지막 구독을 껐다 켜는 동안 깨우기 경로를 잃을 수 있던 구간을 줄입니다. 전면의 명시적 재구독 경로는 유지합니다.
- OS가 연결 유지 콜백을 실행시켜 준 동안에도 오래 멈춘 인증·전송의 복구를 허용합니다. 기존 코드는 같은 콜백이 실행 중이어도 앱이 전면이 아니면 시간 초과 복구 전에 반환했습니다.
- 연결 유지 콜백 사이에 45초가 넘는 공백이 있으면 복구 시간 계산을 새 실행 구간부터 시작합니다. OS가 앱을 중단한 시간을 전송·인증 실패로 오판해 재연결하지 않도록 합니다.
- 진단에 실제 앱 상태와 메모리 내 키 준비 여부, 전면·백그라운드 전환 이벤트를 추가합니다. 키 자체나 메시지 본문은 추가 기록하지 않습니다.

이 변경은 OS의 실행·BLE 예산을 해제하거나, 중단된 앱을 임의 실행하는 기능이 아닙니다. 위치 세션을 처음 시작하는 데 적용되는 전면 조건도 변경하지 않았습니다. 아래에서 확인한 백그라운드 복원과, 모든 잠금 해제·장시간 대기에서의 즉시 복구는 구분합니다.

Android 0.6.7의 두 재연결 사례와 남은 조건은 [재연결 조사](AUTO_RECONNECT_KO.md)에 기록했습니다. 이 브랜치의 변경은 차량 명령을 실행하지 않습니다.

## 실제 기기 확인 범위

- Android 0.6.7 업데이트 직후, 워치 앱을 에이전트가 실행하지 않은 상태에서 자동 인증 기록을 읽었습니다.
- 폰 프로세스를 강제 종료하고 폰 앱만 다시 실행한 뒤에도 새로고침 횟수 0으로 재인증됐습니다.
- 이후 연결 세대 1을 유지한 채 일반 알림 2건의 수신 확인과 대기 0을 읽었습니다.
- 위 세 항목은 Watch 0.5.8과의 결과입니다.
- 검토 중 실행 중단을 통신 지연으로 잘못 계산할 수 있는 부분을 찾아 보강하고 다시 빌드했습니다. 빌드 성공은 실제 워치 조건의 통과와 구분합니다.

### 설치한 Watch 0.5.9의 관찰

- 설치 후 06:48:21 UTC에 `restore.2 → subscribe.retained.background → handshake.commit`, 06:48:22에 `authenticated`를 기록했습니다. 각 이벤트는 `active=false`였습니다. 기존 구독을 끄지 않는 새 경로가 실제 기기에서 실행됐습니다. 설치 후 실행 명령을 한 번 사용했으므로, 이것을 재부팅 후 완전 무조작 실행의 증거로 보지는 않습니다.
- 갤럭시 화면의 **연결 새로고침**을 직접 한 번 눌렀습니다. 06:51:50에 워치가 `active=false` 상태에서 `remote.refresh`를 기록했고, 폰 `refreshCount=1`, 워치 `remoteRefreshCount=1`, 양쪽 연결 유지, 워치 연결 취소 0건을 확인했습니다. 이미 연결된 상태의 요청 전달 결과입니다.
- 폰 앱 프로세스를 강제 종료한 뒤 폰 앱만 다시 실행했습니다. 워치에서는 06:52:20의 서비스 부재 처리 후 06:52:21에 재인증됐고, 해당 이벤트도 모두 `active=false`였습니다. 폰 새로고침 횟수는 0이었습니다. 이 과정에서 에이전트는 워치 앱을 실행하지 않았습니다. Android에서 강제 종료된 앱이 스스로 재시작한다는 뜻은 아닙니다.
- 폰을 종료하면 해당 GATT 서비스도 사라지므로 이 마지막 사례에는 서비스 탐색 실패 및 연결 취소가 각 1건 있었습니다. 이후 자동으로 복구됐으며, 이를 오류 0건으로 표기하지 않습니다.
- 실제 워치 화면은 Device Hub에서 검게 표시됐습니다. **물리 잠금/해제, 장시간 중단 후 복구, 실제 거리 이탈·복귀는 아직 확인하지 못했습니다.** 따라서 모든 조건에서 완벽히 해결됐다고 단정하지 않습니다.
- 워치 등록·키·설정은 유지했고 실제 차량 명령은 실행하지 않았습니다. 원본 기기 기록과 식별자는 공개 저장소에 포함하지 않습니다.
