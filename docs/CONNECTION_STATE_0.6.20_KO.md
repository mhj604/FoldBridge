# Android 0.6.20 — 연결 유지와 수신 대기 구분

**한국어** · [English](CONNECTION_STATE_0.6.20_EN.md) · [현재 버전](CURRENT_STATUS_KO.md)

2026-11-18. Android **0.6.20 / 코드 42**, Watch 설치본은 **0.5.26 / 빌드 60**을 유지합니다. 기존 Android 서명 키로 덮어 설치했습니다. 등록·BLE UUID·암호화 문맥·워치 위치/화면 동작은 변경하지 않았습니다.

## REA로 읽은 상태

수정 전 양쪽 앱 자체 상태는 인증·읽기 수신 중이었습니다. 워치는 실제 네이티브/SwiftUI `background`, 현재 프로세스의 취소 0건·실패 없음·단절 기록 없음이었습니다. 이때 읽은 워치 암호 상태는 잠금 해제였으므로 수시간 암호 잠금의 결과로 표현하지 않습니다.

폰 코드의 `isConnected()`는 BLE 인증 상태와 별개로 마지막 읽기가 10초 이상 늦어지면 false를 반환했습니다. UI와 실행 알림 모두 이를 연결 유무로 사용해, BLE가 유지돼도 응답 대기가 연결 끊김처럼 보일 수 있었습니다. 폰의 `connectionStartedAt`도 읽기 재개 때 알림 기준 시각으로 바뀌는 값이어서 인증 시각이나 실제 연결 수명으로 사용할 수 없었습니다. 이 표시 경로를 실제 무선 단절 전체의 원인으로 확대하지 않습니다.

## 수정 내용

- 수신 준비와 인증된 BLE 링크를 구분합니다. 읽기만 잠시 멈춘 상태는 **연결 유지 중 · 수신 대기**로 설명합니다.
- 인증 링크가 유지되는 동안은 폰의 같은 연결 알림 채널을 사용하며, 읽기 지연으로 대기/연결 채널을 오가지 않습니다. 수신 재개를 기다린다는 본문으로 바뀝니다. 실제 연결/인증이 없으면 기존 대기 채널로 전환합니다.
- 앱 자체 상태 파일에 `authenticatedLink`, `deliveryResponsive`, 실제 `authenticatedAt`, `notificationCutoffAt`, 최근 읽기 시각·읽기 나이, 10초 이상 읽기 재개 횟수·최대 간격, 실제 native 단절 횟수·시각을 따로 남깁니다. 내용·상대 키는 기록하지 않습니다.
- 읽기 지연 중 새 알림 전달 조건과 재개 때 오래된 대기열을 비우는 규칙은 유지합니다. 표시만 연결로 바꾸고 수신이 계속된다고 주장하지 않습니다.

## 설치 결과와 남은 범위

APK 빌드와 REA 덮어 설치가 완료됐습니다. 이후 앱 자체 상태의 실제 빌드 42, `authenticatedLink=true`, `deliveryResponsive=true`를 읽었습니다. 워치 앱을 여는 명령 없이 같은 빌드 60 프로세스의 `background`에서 인증·읽기 수신이 기록됐습니다. 새 워치 설치나 위치 세션 재준비는 하지 않았습니다.

이것은 업데이트 뒤 복원 관측이며, 수시간/밤새 잠금·반복적인 거리 이탈/복귀·모든 무선 반복 단절의 해결을 뜻하지 않습니다. 강제 거리/잠금 시험·합성 알림·차량 명령·시스템 로그는 사용하지 않았습니다. 실제 무선 단절이 생기면 새 native 카운터와 워치 종료 이벤트를 함께 보고, 읽기 중단만 생기면 수신 재개 간격을 별도로 봅니다. 자동 메인 화면 표시 문제는 계속 보류합니다.
