# Android 0.6.9 / Watch 0.5.12: 백그라운드 인증 재개 수정

**한국어** · [English](WATCH_0.5.12_BACKGROUND_AUTH_EN.md)

`fix/watch-background-reconnect` 브랜치의 수정 후보입니다. Android 0.6.9-local / 코드 25와 Watch 0.5.12 / 빌드 36을 기존 앱에 덮어 설치하며 등록·상대 키·차량 설정을 유지합니다. [후보 APK](../artifacts/android/FoldBridge-Local-0.6.9.apk).

## 관찰한 문제

기존 Watch 빌드 35는 백그라운드에서 서비스 검색과 구독까지 진행한 뒤 `handshake.commit` 직후 연결 종료를 반복했습니다. 폰에서도 물리 연결과 구독이 반복됐습니다. 따라서 단순히 워치 검색이 전혀 안 되는 상태와 달랐습니다. 한 차례 Bluetooth 암호화 시간 초과도 있었지만, 모든 종료의 원인으로 확정하지 않았습니다.

Mac과 폰이 서로 다른 Wi-Fi 주소 대역에 있어 진단 연결도 막혀 있었습니다. 이는 Galaxy–Watch BLE 경로와 별개의 문제입니다. 앱 사용에 같은 Wi-Fi나 Mac은 필요하지 않습니다.

## 변경

- 폰은 저장된 상대가 구독하면 기존 750ms 대기 대신 구독 응답 직후 시작 신호를 보냅니다. 주기적인 빈 깨우기 메시지는 추가하지 않습니다.
- 백그라운드 워치는 먼저 구독을 준비하고 시작 신호를 받은 콜백에서 인증을 시작합니다. 시작 신호와 이미 진행 중인 인증이 겹쳐도 인증 상태를 다시 초기화하지 않습니다.
- 백그라운드 연결 종료 콜백에서는 다음 연결 요청을 즉시 시스템에 등록합니다. 실행이 중단될 수 있는 지연 타이머에만 맡기지 않습니다.
- 폰 새로고침은 구독이 없는 경우 광고를 실제로 다시 시작합니다. 정상 인증된 링크에서는 기존 암호화된 새로고침을 사용해 연결을 취소하지 않습니다.
- 시작 신호는 연결 준비용이며 상대 인증을 대신하지 않습니다. 기존 저장 키 검증과 암호화 확인을 통과해야 알림·차량 정보가 전달됩니다.

이 변경은 인증 재개 순서를 다듬습니다. 이전 750ms 대기가 모든 끊김의 원인이었다고 단정하지 않습니다.

## 실제 기기 결과 — 2026-11-08 KST

양쪽 빌드와 덮어 설치를 완료했습니다. 새 워치 코드를 한 번 실행해 준비한 후 홈 화면으로 보냈고, 그 뒤 워치 앱을 다시 열지 않았습니다.

1. 폰 프로세스 종료 후 폰 앱만 다시 실행: 워치의 서비스 재탐색 → 시작 신호 → 재인증이 모두 `active=false` 상태에서 완료됐습니다.
2. 폰에서 연결 새로고침: 폰 `refreshCount=1`, `softRefreshCount=1`, 인증 상태 유지가 기록됐습니다. 이는 정상 링크의 새로고침 결과입니다.
3. 폰 설정의 **연결 중지**로 서비스를 종료한 후 사용자가 폰의 **워치 연결**만 한 번 누름: 워치 구독 → `handshake.await.bootstrap` → `remote.wake` → `handshake.commit` → `authenticated`가 약 1초 안에 진행됐습니다. 전 과정 `active=false`, 워치 자체 새로고침 횟수 0, 오류 기록 0이며 저장된 등록은 유지됐습니다.

세 번째 동작은 명시적으로 중지한 서비스를 다시 켜는 **워치 연결** 버튼입니다. 끊긴 물리 링크에 대해 **연결 새로고침**만 누르는 모든 조건을 입증한 것으로 혼동하지 않습니다. 폰의 Android `watchActive`는 워치 UI 전면 여부가 아니라 연속 처리 가능 상태도 포함합니다. 실제 UI 상태는 워치 `active`와 이벤트 기록으로 구분했습니다.

## 남은 범위

장시간 잠금·OS 종료 후 잠금 해제, 실제 거리 이탈·복귀, 물리 링크가 사라진 상태에서 폰 새로고침만으로 복구하는 조건은 계속 남아 있습니다. 짧은 서비스 재시작 성공을 모든 조건에서의 완전 해결로 표시하지 않습니다. 기존 [미완료 목표](WATCH_0.5.10_CANDIDATE_KO.md#미완료-작업과-다음-수정-목표--2026-11-07)를 유지합니다.

Apple은 구독한 Bluetooth 특성 변경을 통한 백그라운드 실행과 시스템의 연결 보존을 설명하지만 실행 예산도 둡니다. [공식 설명](https://developer.apple.com/videos/play/wwdc2022/10135/) · [백그라운드 작업](https://developer.apple.com/documentation/watchkit/using-background-tasks).

작업 종료 시에는 등록을 삭제하지 않고 폰의 **연결 중지**로 실제 연결을 중지합니다. 다음 사용 시 폰의 **워치 연결**을 한 번 눌러 서비스 사용을 다시 켭니다. 정상적인 거리 이탈은 명시적 연결 중지와 다릅니다.
