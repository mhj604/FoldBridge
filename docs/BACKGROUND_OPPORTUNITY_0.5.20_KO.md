# Watch 0.5.20 — 실행 기회에서 중단된 복구 단계 재개

[English](BACKGROUND_OPPORTUNITY_0.5.20_EN.md) · [문서 목록](README.md)

2026-11-15, Watch·차량 위젯 **0.5.20 / 빌드 46**. Android는 **0.6.15-local / 코드 33**을 유지합니다. 기존 등록·신원 키·상대 키·차량 설정은 유지합니다. [Android APK](https://github.com/mhj604/WatchBridge/releases/download/connection-v0.5.19/FoldBridge-Local-0.6.15.apk).

## 실행 상태 해석 정정 (2026-11-15)

이 기록의 `active=false`는 앱이 활성 상태가 아니라는 뜻입니다. 함께 기록된 `applicationState=1`은 SDK의 `inactive`이며, `background=2`나 암호 잠금을 입증하지 않습니다. 따라서 아래의 백그라운드 성공 표현은 **워치 앱 실행 명령 없이 비활성 상태에서 인증이 완료된 결과**로 한정해 읽어야 합니다. 장시간 잠금·실제 거리 복귀의 완료 근거로 사용하지 않습니다.

## 새로 찾은 누락

앞선 코드는 백그라운드 앱 새로고침을 받아도 기존 peripheral이 물리적으로 연결돼 있으면 탐색·인증 중간 단계를 재개하지 않고 돌아갈 수 있었습니다. 위치/유지보수 콜백의 인증 복구에는 연속 실행 시간 조건도 있었습니다. 중단 후 실행될 때마다 기준 시간을 현재로 바꾸므로 짧고 간헐적인 실행 기회에서는 복구 조건에 도달하지 못할 수 있었습니다.

또한 서비스 무효화 방어가 특성 콜백에만 있어, 최초 캐시 확인에서 무효화된 서비스를 선택하면 콜백을 거절한 뒤 실제 탐색 요청을 내지 않는 경로가 남았습니다. 범위 밖에서 이미 시스템 연결을 기다리는 백그라운드 작업도 앱 할 일이 없는데 만료까지 붙잡고 있었습니다.

이들은 코드에서 찾은 누락입니다. 특정 장시간 잠금·거리 이탈 현상의 단일 원인으로 확정하지 않습니다.

## 변경

- OS의 앱 새로고침·위치/유지보수 실행 기회에서 공통 복구 함수를 호출합니다. 서비스 대기는 탐색을 재개하고, 90초 동안 관련 진행이 없는 탐색·미완료 인증은 같은 물리 링크에서 다시 준비합니다.
- 90초는 백그라운드에서 계속 도는 타이머나 연결 지연이 아닙니다. 실제 실행 기회에만 살피며, 정상 인증된 연결은 침묵 시간 때문에 취소하거나 재인증하지 않습니다.
- 관련 탐색 콜백과 인증 프레임/쓰기 응답을 진행으로 기록합니다. 연속 90초 동안 앱이 실행돼야 한다는 조건을 제거합니다.
- Bluetooth 알림 실행 기회에는 곧 들어올 기존 응답을 먼저 처리하도록 인증 난수를 바꾸지 않습니다. 독립적인 앱 새로고침 기회에서만 중단된 단계를 복구합니다.
- 최초 캐시 확인도 무효화된 서비스 객체를 제외해 실제 탐색으로 넘어갑니다.
- 범위 밖에서 native pending connect/복원 검색만 남고 처리할 프레임·알림이 없으면 백그라운드 작업을 완료합니다. 시스템 연결·검색 요청은 취소하지 않습니다. 진행 중인 인증/전송은 유지합니다.

새 진단 필드는 `executionOpportunityRepairs`, `nativeWaitTaskCompletions`입니다. 위치 세션을 백그라운드에서 새로 시작하거나 운동·오디오·서버·아이폰 중계를 추가하지 않습니다.

## 실제 앱 기록과 설치

이번 작업 시작 때 폰 33과 워치 45는 이미 인증돼 있었고 워치는 `active=false`였습니다. 워치 45 기록에는 서비스 부재 중 백그라운드 대기 37회 뒤 폰 서비스 변경을 받아, 워치 앱 실행 명령 없이 구독·빠른 인증을 완료한 과정이 있었습니다. 이 기록을 실제 거리 이동이나 장시간 암호 잠금의 증거로 확대하지 않습니다.

빌드 46 상태: 빌드·덮어 설치가 성공했습니다. 워치 앱 실행 명령 없이 새 프로세스가 빌드 46, `active=false`, `connected=true`, 빠른 인증 완료 1, 오류·조각 폐기 0을 기록했습니다. 인증 단계는 154ms였으며 전체 연결 시간이 아닙니다. `executionOpportunityRepairs=0`, `nativeWaitTaskCompletions=0`이므로 새 복구 분기의 실제 실행을 입증하는 결과는 아닙니다.

별도 QA 시나리오·시스템 로그·관리자 암호·실제 차량 명령은 사용하지 않았습니다. 물리 거리 이탈·복귀를 대신 수행하지 않았습니다. 새 수정 분기가 실제로 실행되지 않았다면 설치 직후 성공만으로 해당 분기까지 완료 판정하지 않습니다.

## 완료 범위와 한계

앱 내부의 복구 누락을 보완했으며, **무기한 잠금과 모든 실제 거리 복귀에서 무조건 자동 연결된다는 보장은 하지 않습니다.** Apple이 부여하는 백그라운드 실행 기회·예산이 있어야 다음 앱 단계를 처리할 수 있습니다. 앱 새로고침의 30분 선호 시각은 정확한 실행 예약이 아닙니다. 예산 소진 상태를 앱이 강제로 해제하는 API를 추가한 것은 아닙니다.

[Apple의 백그라운드 Bluetooth와 예산 설명](https://developer.apple.com/documentation/watchkit/using-background-tasks) · [할 일이 끝난 백그라운드 작업 완료](https://developer.apple.com/documentation/watchkit/wkrefreshbackgroundtask/settaskcompleted()).

## 작업 종료

폰의 **설정 → 연결 중지**를 직접 선택했습니다. 앱 상태에 `bridgeRunning=false`, `centralPresent=false`, `subscribed=false`, `authenticated=false`, `status=중지됨`이 기록됐습니다. 등록·키·차량 설정은 유지했습니다. Mac의 무선 디버깅도 종료합니다.

기존 주 1회 Mac 서명 갱신 소스를 설치한 빌드 46의 커밋에 맞춥니다. 갱신은 지금 실행하지 않습니다. 워치 인터넷만의 무료 자동 서명은 별도 미완료 항목입니다.
