# Android 0.6.13 / Watch 0.5.17 — 재검색 줄이기와 연결 알림 분리

> 버전별 조사·변경 기록입니다. 여기의 “현재/완료/미해결”은 해당 시점 기준이며 최신 설치 안내가 아닙니다. [현재 버전과 작업 상태](CURRENT_STATUS_KO.md).

[English](CONNECTION_0.5.17_EN.md) · [문서 목록](README.md)

2026-11-15에 Android **0.6.13-local / 코드 31**, Watch·차량 위젯 **0.5.17 / 빌드 43**을 기존 앱에 덮어 설치했습니다. 등록·키·차량 설정은 유지합니다. [APK 다운로드](https://github.com/mhj604/WatchBridge/releases/download/connection-v0.5.17/FoldBridge-Local-0.6.13.apk).

## 실제로 읽은 상태

갤럭시에는 앞선 0.6.12가 아직 적용되지 않고 0.6.11 / 29가 설치돼 있었습니다. 이번에 0.6.12를 거쳐 0.6.13으로 업데이트했습니다. 워치 42의 앱 기록에는 백그라운드 구독·인증 시작 뒤 오류 없는 종료와 재접속이 약 2~3초마다 반복됐습니다. 앱의 명시적 연결 취소 횟수는 0, 폰은 GATT 서버의 물리 연결 종료 없이 인증 시작을 반복하는 상태였습니다. 기기가 멀어졌기 때문이라고 단정할 기록이 아닙니다.

워치 앱을 한 번 실행하자 폰에서 인증 완료 상태가 읽혔습니다. 이 결과는 백그라운드 실행 조건이 영향을 주는 정황이며, 오류 없는 모든 종료의 원인을 확정하지는 않습니다. 시스템 로그는 수집하지 않았습니다.

## 워치 변경

기존 코드는 저장된 상대에 대한 시스템 연결 요청과 함께 복구용 재검색도 시작했습니다. Apple은 백그라운드 재검색과 BLE 알림 깨우기가 실행 예산을 공유하며, 초과하면 백그라운드 연결이 제한된다고 설명합니다. [Apple의 BLE 설명](https://developer.apple.com/videos/play/wwdc2022/10135/).

이제 백그라운드에서는 저장된 상대의 시스템 연결 요청을 우선 유지합니다. 이미 물리 연결된 상대의 서비스 대기를 위해 다시 검색하지 않습니다. 주소가 바뀌거나 캐시가 없는 경우의 검색은 남기되, 저장된 상대의 연결 요청 후 30초가 지나야 시작하고 앱 프로세스 내에서 30분보다 자주 시작하지 않습니다. 이 30초는 정상 재연결을 늦추는 타이머가 아닙니다. 시스템 연결은 즉시 요청하며 보조 검색만 제한합니다. 전면 검색은 유지합니다. 앱 상태에 `backgroundRecoveryScans`를 추가합니다.

이전 0.5.16의 불필요한 연결 취소 제거도 유지합니다. 모든 OS·전파 단절을 막거나 무기한 잠금 수신을 보장하는 수정은 아닙니다. 지속 연결·장시간 잠금·실제 거리 복귀의 최종 완료 판정은 남아 있습니다.

## 실제 연결됐을 때만 폰 알림 표시

상시 서비스는 유지하면서 알림 채널을 분리합니다.

- **실제 연결 알림** (`connection_online`): 상대·구독·암호화 인증이 모두 있어야 표시합니다.
- **연결 대기 알림** (`connection_waiting`): 서비스가 상대를 기다리는 동안 사용하는 채널입니다. Android 설정에서 이 채널만 끌 수 있습니다.

이번 갤럭시에서는 대기 채널만 끄는 설정을 적용했고, 앱 상태의 `waitingNotificationHidden=true`를 읽었습니다. 전경 서비스를 중지하거나 앱 전체 알림·다른 앱의 알림 접근을 끄지 않습니다. Android의 별도 실행 중 앱 목록에는 서비스가 남을 수 있습니다.

다른 사용자는 **WatchBridge → 설정 → 연결 알림 표시 → 설정 열기 → 연결 대기 알림 끄기**로 같은 설정을 사용할 수 있습니다. 실제 연결 채널은 켜 둡니다. 자동 재연결과 워치 알림 전달은 유지됩니다. Android·watchOS의 한국어·영어 리소스도 함께 갱신했습니다.

## 설치 후 상태와 작업 종료

두 설치가 성공했고 워치 앱을 한 번 실행했습니다. 폰 앱 상태에는 `build=31`, `authenticated=true`, `subscribed=true`, 대기 프레임·메시지 0, 앱 연결 취소 0이 기록됐습니다. 이는 설치 직후 결과이며 장시간 안정성 결과로 확대하지 않습니다. 차량 명령은 실행하지 않았습니다.

종료 때 폰의 **설정 → 연결 중지**를 직접 선택했습니다. 이후 앱 상태는 `bridgeRunning=false`, `centralPresent=false`, `subscribed=false`, `authenticated=false`, `status=중지됨`으로 기록됐습니다. 등록 해제·키 삭제·차량 설정 초기화는 하지 않았습니다. Mac 진단 연결 종료와 갤럭시–워치 연결 종료는 다릅니다.
