# Android 0.6.14 / Watch 0.5.18 — 자동 복구와 빠른 재인증

[English](FAST_RECONNECT_0.5.18_EN.md) · [문서 목록](README.md)

2026-11-15에 Android **0.6.14-local / 코드 32**, Watch·차량 위젯 **0.5.18 / 빌드 44**를 기존 앱에 덮어 설치했습니다. 등록·개인 키·상대 키·차량 설정은 유지합니다. [APK 다운로드](https://github.com/mhj604/WatchBridge/releases/download/connection-v0.5.18/FoldBridge-Local-0.6.14.apk).

## 실행 상태 해석 정정 (2026-11-15)

이 기록의 `active=false`는 앱이 활성 상태가 아니라는 뜻입니다. 함께 기록된 `applicationState=1`은 SDK의 `inactive`이며, `background=2`나 암호 잠금을 입증하지 않습니다. 따라서 아래의 백그라운드 성공 표현은 **워치 앱 실행 명령 없이 비활성 상태에서 인증이 완료된 결과**로 한정해 읽어야 합니다. 장시간 잠금·실제 거리 복귀의 완료 근거로 사용하지 않습니다.

## 지연을 만드는 경로와 수정

이전 워치 기록에서 폰 서비스가 없을 때 서비스 탐색이 약 31초 간격으로 반복됐습니다. 0.5.17은 저장된 상대의 시스템 연결 요청을 유지하지만, 백그라운드 보조 검색에 30초 지연·30분 재시작 제한을 적용했습니다. 서비스가 다시 나타났을 때의 빠른 복구 기회를 줄이는 경로였습니다. 인증 뒤에도 `recoveryScanning=true`가 남은 기록도 있었습니다. 다만 현재 작업 시작 시 기존 세션은 이미 연결돼 있었으므로 모든 반복 끊김을 한 원인으로 단정하지 않습니다.

0.5.18은 다음을 변경합니다.

- 저장된 상대에 대한 시스템 자동 재연결 요청과 같은 peripheral을 유지합니다. 백그라운드 종료 콜백에서 바로 다시 요청하며 반복적인 연결 취소를 추가하지 않습니다.
- 복구 중 서비스 필터 검색 하나를 연결·서비스 탐색·인증까지 유지합니다. 30초/30분 제한을 제거하고 인증 성공 시 검색을 종료합니다. 콜백마다 검색을 중지·재시작하지 않습니다.
- 서비스 탐색 재시도 간격은 1·2·4·8초이며 이후 8초 상한입니다. 별도 연결 대기 보조 검색은 3초 뒤 요청하지만 이미 진행 중인 검색은 그대로 사용합니다.
- 늦게 도착한 중복 서비스·특성 콜백이 진행 중인 인증을 초기화하지 않도록 합니다. 같은 링크에서 재인증할 때 기존 ATT write 응답과 새 세션 전송 슬롯을 구분합니다.
- 저장된 상대끼리는 아래 빠른 재인증을 사용합니다. 최초 등록의 코드 비교는 그대로입니다.

0.5.17 문서의 검색 제한 설명은 과거 동작입니다. 정상 연결의 새로고침은 기존 링크와 세션을 유지하며, 알림 재전송 cutoff·차량 제어·본문 배치는 바꾸지 않습니다.

## 저장된 상대의 빠른 인증

기존 P-256 고정 상대 키와 새 양쪽 난수로 서로를 확인합니다. 공개 키를 다시 조각내 보내는 교환을 생략하며 인증 메시지는 `ready` 이전 6개에서 3개로 줄어듭니다. 폰은 워치의 암호화된 확인을 받은 뒤에만 인증 완료로 처리합니다. 이전 폰과의 실패는 기존 commit/reveal 방식으로 돌아갑니다. 구체적인 HKDF/HMAC 문맥·메시지는 [프로토콜](PROTOCOL.md#저장된-상대의-빠른-재인증-android-0614--watch-0518)에 기록했습니다.

## 설치 뒤 읽은 실제 앱 상태

두 설치가 성공했고 **이번 작업에서 워치 앱 실행 명령을 보내지 않았습니다**. 새 워치 프로세스의 상태는 빌드 44, `active=false`, `connected=true`, 빠른 인증 시도/완료 각각 1, 앱 연결 취소 0, 오류 없음, `recoveryScanning=false`였습니다. 폰도 빌드 32, `authenticated=true`, `watchActive=false`, 빠른 인증 완료 1을 기록했습니다. 폰 기록의 인증 완료 뒤 약 3분 시점까지 `disconnectCount=0`, 인증 유지가 읽혔습니다.

인증 단계만 워치에서 **2,362ms**, 폰에서 **3,002ms**였습니다. 두 값은 각 앱의 측정 시작점이 다르며, 무선 탐색·OS 대기·전체 연결 소요 시간을 뜻하지 않습니다. 과거 버전 대비 전체 연결 속도 비율을 주장하지 않습니다.

이번 백그라운드 재실행에서는 `continuousRequested=false`였습니다. 위치 기반 연결 유지 요청이 자동 복원됐다고 주장하지 않습니다. BLE 복원만으로 연결된 결과입니다. 위치 세션은 전면 실행 조건이 있으므로 이번에 사용자 대신 앱을 열어 시작하지 않았습니다. 저장된 설정은 삭제하지 않았습니다.

시스템 로그·관리자 인증·실제 차량 명령·별도 QA 시나리오는 진행하지 않았습니다. 기록은 앱 자체 상태에 한정하며 본문·키·기기 식별자를 공개하지 않습니다.

## 남은 조건

장시간 잠금·프로세스 중단 후 자동 복구, 실제 거리 이탈·복귀에서의 지속 동작과 모든 오류 없는 연결 종료의 원인은 여전히 관찰이 필요합니다. 가까이 있다는 이유만으로 OS·전파·전원에 의한 단절을 없앨 수 있다고 약속하지 않습니다. 현재 성공 기록을 무기한 지속 연결 결과로 확대하지 않습니다.

워치 인터넷만의 무료 서명 갱신은 별도 미완료 목표입니다. 기존 주 1회 Mac 예약은 이번 빌드의 커밋 소스와 프로파일에 맞춥니다. 설치 파일의 가장 이른 만료는 **2026-11-20 17:10:54 KST**이며 이번 빌드가 7일 연장한 것은 아닙니다.

## 작업 종료

사용자가 폰의 **설정 → 연결 중지**를 선택한 뒤 앱 상태에서 `bridgeRunning=false`, `centralPresent=false`, `subscribed=false`, `authenticated=false`, `status=중지됨`을 읽었습니다. 실제 갤럭시–워치 연결이 중지됐으며 등록·키·차량 설정은 지우지 않았습니다. Mac의 진단 연결도 종료합니다.
