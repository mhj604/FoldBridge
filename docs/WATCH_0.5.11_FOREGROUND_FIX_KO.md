# Watch 0.5.11 / 빌드 35: 앱 실행 후 연결 지연 퇴행 수정

**한국어** · [English](WATCH_0.5.11_FOREGROUND_FIX_EN.md)

Android 0.6.8-local / 코드 24는 유지하고 Watch를 0.5.11 / 빌드 35로 갱신합니다. 기존 등록·키·차량 설정을 유지합니다.

## 왜 이전보다 느려졌나요?

0.5.10에서 반복 연결 실패를 줄이려고 `nextConnectAttempt` 대기를 추가했지만, 앱 활성화 처리인 `setActive(true)`에서는 이 대기를 해제하지 않았습니다. 앱을 열어도 `reconnect()`와 광고 수신 경로가 대기 시간에 막힐 수 있었습니다. 반면 워치의 연결 새로고침은 이 시간을 초기화한 뒤 연결을 다시 시작했습니다. 즉, 앱 실행과 워치 새로고침의 복구 동작에 차이가 생긴 코드 퇴행입니다. 사용자 설정이나 등록 정보를 지워야 하는 문제가 아닙니다.

실제 0.5.10 기록에서도 앱이 전면으로 전환된 뒤 약 18초 후에야 연결·인증이 진행된 구간을 읽었습니다. 이 기록만으로 사용자가 겪은 모든 연결 중단의 원인을 확정하지는 않습니다.

## 수정

- 앱이 전면으로 전환되면 예약된 재시도와 대기 시간을 **연결 재개보다 먼저** 초기화합니다.
- 이미 끊긴 기기에 남은 자동 재연결 플래그도 정리해 저장된 상대에 다시 연결을 요청합니다.
- 같은 물리 링크에서 서비스가 나타나기를 기다리는 중이라면 앱을 열었을 때 즉시 서비스 탐색을 재개합니다.
- 정상 인증된 연결을 앱을 열 때마다 취소하지 않습니다. 백그라운드 연속 실패에 대한 대기 정책도 유지합니다.
- 진단에 남은 재시도 대기 시간을 추가합니다.

이 변경은 워치 앱을 열어도 재시도 대기를 물려받던 퇴행 경로를 제거합니다. 폰만으로 백그라운드 연결하기, 장시간 잠금 후 복구, 실제 거리 이탈·복귀는 여전히 [미완료 목표](WATCH_0.5.10_CANDIDATE_KO.md#미완료-작업과-다음-수정-목표--2026-11-07)입니다. 모두 해결됐다고 표시하지 않습니다.

## 설치 기록

2026-11-07 기존 앱 위에 설치했습니다. 새 프로세스의 빌드 35, 인증된 연결, 워치 새로고침 횟수 0, 남은 재시도 대기 0을 읽었습니다. 설치 후 앱 실행 명령을 사용한 결과이며, 장시간 잠금이나 실제 거리 이탈·복귀의 완료 기록은 아닙니다.
