# Watch 0.4.7 / Android 0.5.2 — 연결 유지 갱신과 알림 카드 여백

**한국어** · [English](RELEASE_WATCH_v0.4.7_EN.md) · [전체 문서](README.md)

- Watch **0.4.7 / build 21**
- Android **0.5.2-local / versionCode 13**

## 바뀐 동작

정상 연결에서 갤럭시 또는 워치 한쪽의 **연결 새로고침**을 누르면, 암호화된 갱신·동기화 요청을 보내며 기존 Bluetooth 연결과 세션을 유지합니다. 폰 버튼을 누른 뒤 1.5초 만에 연결을 취소하던 동작과 워치의 주기적 ping/짧은 응답 제한을 제거했습니다.

Android는 여러 앱과 시스템 서비스가 GATT 데이터베이스를 공유합니다. 실제 기기 기록에서 삼성 기기 연결 서비스의 등록 변경과 워치의 서비스 무효화가 같은 시각에 나타났습니다. 정상 인증 중이면 통신 특성을 다시 찾고 구독을 복구하며, 이 이벤트만으로 암호화 세션을 버리지 않습니다. 물리적 끊김이 연속될 때는 재시도 간격을 늘립니다.

워치 프로세스가 복원된 경우에는 이전 세션 키를 재사용하지 않습니다. 저장된 상대 키를 확인하고 새 nonce로 같은 Bluetooth 링크에서 인증합니다. CCC 재구독과 이전 ATT 전송 응답 분리, MTU 복원도 보완했습니다. 알림 표시 ACK 지연은 미전달 대기로 남기며 정상 BLE 연결을 취소하지 않습니다.

상세 알림의 작은 원본 아이콘·글씨 위치는 유지하고 카드 **아래 여백만 4pt** 줄였습니다. 글꼴·줄 높이·아이콘 크기를 바꾸지 않았습니다. [예문 화면 비교](https://github.com/mhj604/FoldBridge/blob/local-ble/docs/NOTIFICATION_LAYOUT_COMPARISON_KO.md)

## 실제 기기에서 관찰한 결과

Galaxy Z Fold7과 Apple Watch Ultra 2 / watchOS 27.0.1에 같은 서명으로 업데이트했습니다. 위치 연결 유지가 켜진 상태이며 워치가 강제 종료된 상황은 아닙니다.

| 조작/기록 | 결과 |
| --- | --- |
| 사용자: 워치를 잠근 뒤 폰에서만 새로고침 1회 | 워치 `active=false`에서 원격 갱신 수신 1회 증가 |
| 갱신 전후 워치 세션 | 같은 프로세스·같은 세션 세대 유지 |
| 갱신 전후 폰 세션 | 같은 세션 세대 유지, 연결 취소 요청 0회 |
| 갱신 후 약 90초까지 워치 기록 | 같은 프로세스·세션 유지, 추가 끊김·오류 기록 없음 |
| 갱신 뒤 | 양쪽 인증됨, 오류 기록 0건, 미전달 대기열 0건 |

초기 수정본에서 잠금 중 실패가 재현됐으며 위 표는 추가 수정한 빌드 21의 결과입니다. REA로 폰의 로그와 상태 파일을 읽고 워치 앱의 단계 기록과 대조했습니다. 실제 알림 내용·기기 식별자·원본 기기 로그는 공개하지 않습니다.

## 적용 및 범위

기존과 같은 Android 서명과 워치 Bundle ID로 업데이트하면 등록 키·필터·미전달 대기열을 유지합니다. 앱을 삭제하거나 코드를 다시 등록할 필요는 없습니다.

이 변경은 폰에서 워치 앱을 무조건 강제 실행하는 기능이 아닙니다. 유지 중인 BLE 연결에 특성 변경이 오면 watchOS가 허용하는 백그라운드 실행 기회에 처리합니다. 강제 종료·재부팅 후 첫 잠금 해제 전·Bluetooth 꺼짐·범위 이탈·OS의 실행/수신 예산 소진에서는 즉시 복구를 보장하지 않습니다. 한도 안내가 나오거나 복원이 멈추면 워치 앱을 한 번 열어야 할 수 있습니다. [Apple 백그라운드 작업](https://developer.apple.com/documentation/watchkit/using-background-tasks)
