# Android 0.6.15 / Watch 0.5.19 — 백그라운드 복구 요청 보존

[English](BACKGROUND_RECOVERY_0.5.19_EN.md) · [문서 목록](README.md)

2026-11-15 수정 후보: Android **0.6.15-local / 코드 33**, Watch·차량 위젯 **0.5.19 / 빌드 45**. [APK 다운로드](https://github.com/mhj604/FoldBridge/releases/download/connection-v0.5.19/FoldBridge-Local-0.6.15.apk). 기존 등록·신원 키·고정 상대 키·차량 설정을 유지합니다.

## 실제 기록과 코드에서 찾은 문제

작업 시작 때 폰 서비스는 앞선 종료 요청대로 중지돼 있었습니다. 이는 등록 해제와 다릅니다. 워치 기록에는 서비스 변경 후 `rediscovering`에 머문 상태, 수신 조각 폐기 29건, 이후 Bluetooth 연결 시간 초과가 있었습니다. 이를 장시간 잠금이나 거리 이탈 자체가 입증된 기록으로 취급하지 않습니다.

코드에는 다음 복구 누락이 있었습니다.

- 연결 실패 시 재시도를 앱 타이머에만 예약하는 경로가 있었습니다. 백그라운드에서 타이머가 실행되지 않으면 네이티브 연결 요청이 남지 않을 수 있었습니다.
- 복원된 peripheral이 저장된 UUID와 일치하지 않는 검색 전용 복원에서, 검색을 끊고 즉시 재개를 요청하지 않았습니다. 다음 Bluetooth 상태 콜백이 없으면 멈출 수 있었습니다.
- 서비스를 다시 찾는 중 두 번째 서비스 무효화가 오면 이를 무시했습니다. 무효화된 특성 응답을 계속 기다리거나 이전 서비스 객체를 사용할 수 있었습니다.
- 폰이 CCC 구독 해제를 수락해도 상대 선택 상태를 남겼습니다. Android의 공유 물리 링크가 유지되면 새 광고가 막힐 수 있었습니다.

## 변경

백그라운드의 일시적 연결 실패에서는 OS에 즉시 저장 상대 연결을 요청합니다. 전면 대기 타이머가 남은 채 백그라운드로 전환할 때도 이를 네이티브 연결 요청으로 넘깁니다. 다만 잘못된 인자·시스템 연결 수 제한·지원하지 않는 동작·백그라운드 예산 소진처럼 즉시 반복해도 요청을 보존할 수 없는 오류는 빠른 실패 루프를 만들지 않고 후속 OS 상태/예약 실행 기회를 기다립니다.

검색 전용 복원은 기존 서비스 필터 검색을 보존하고 재개를 명시적으로 요청합니다. 같은 UUID의 새 peripheral 객체가 전달되면 해당 객체와 delegate를 채택합니다. 서비스 정보가 연속 무효화되면 최신 서비스를 다시 찾고, 무효화된 서비스 객체의 늦은 응답은 사용하지 않습니다. 연결 종료 뒤 진단 기록도 변경된 상태로 저장해 이전 `connected=true`가 마지막 상태로 남는 문제를 줄였습니다.

폰은 CCC 해제 시 앱 구독 선택과 세션만 정리하고 광고를 재개합니다. 저장된 상대 키를 지우거나 공유 물리 Bluetooth 링크를 강제로 끊지 않습니다. 다음 구독은 기존 키로 새 인증을 진행합니다.

빠른 재인증, 정상 링크를 유지하는 새로고침, 알림 cutoff, 차량 명령 처리, 알림 레이아웃은 이전 버전을 유지합니다.

## 설치와 관찰 범위

Android 33과 Watch 45 덮어 설치가 성공했습니다. 워치 앱 실행 명령 없이 새 프로세스가 `active=false`, `connected=true`, 빠른 인증 완료 1, 오류·조각 폐기 0을 기록했습니다. 폰도 인증 완료, `watchActive=false`였습니다. 처음 설치 직후 인증 단계는 워치 **226ms**, 폰 **173ms**였습니다. 무선 탐색·OS 대기를 포함한 전체 재연결 시간은 아닙니다.

최종 설치 이후 상태: 빌드 45의 백그라운드 연결 상태와 오류·수신 조각 폐기 0이 읽혔습니다. 실제 알림은 워치 표시 요청 수가 2 증가했고 폰 ACK가 2였습니다. 이는 알림 등록 요청의 수락이며 사용자가 화면을 읽거나 진동을 느꼈다는 뜻은 아닙니다. 새 복구 분기 카운터는 0이어서 해당 실패 조건을 현장에서 모두 거쳤다는 근거로 사용하지 않습니다.

새 진단 필드는 `backgroundConnectResubmissions`, `scanOnlyRestorations`, `repeatedServiceChanges`와 폰 `subscriptionReleases`입니다. 카운터가 0인 수정 경로까지 실제로 발생해 해결됐다고 주장하지 않습니다. 시스템 로그·관리자 암호·실제 차량 명령·별도 QA 시나리오·거리 이동 요청은 사용하지 않았습니다.

## 남아 있는 조건과 시스템 동작

이번 변경은 앱이 복구 요청을 남기지 못하는 경로를 보완한 것입니다. **장시간 암호 잠금과 실제 거리 이탈 후 복귀에서 무조건 자동 복구된다는 완료 판정은 아직 하지 않았습니다.** 요청에 따라 별도 현장 QA를 실행하지 않았고, 물리적인 거리 이동도 대신 수행하지 않았습니다.

Apple은 범위 이탈 뒤 종료 콜백에서 연결을 다시 요청하면 가까워졌을 때 시스템이 연결을 재개한다고 설명합니다. 한편 반복 단절 시 재연결 거리가 줄어들 수 있고, 백그라운드 검색·timely alert에는 공유 실행 예산이 있습니다. 이 예산 소진·강제 종료·전원/전파 문제를 새 코드가 제거하지는 않습니다. [Apple: Bluetooth 재연결과 실행 제한](https://developer.apple.com/videos/play/wwdc2022/10135/) · [백그라운드 작업](https://developer.apple.com/documentation/watchkit/using-background-tasks).

위치 세션은 전면에서 시작해야 합니다. 설치 뒤 백그라운드 연결 성공을 위치 세션 복원으로 표시하지 않습니다. [Apple: 백그라운드 세션](https://developer.apple.com/documentation/watchkit/enabling-background-sessions).

## 종료와 서명 소스

폰에서 **설정 → 연결 중지**를 선택했습니다. 종료 후 `bridgeRunning=false`, `centralPresent=false`, `subscribed=false`, `authenticated=false`가 기록됐습니다. 등록 해제·키 삭제·차량 설정 초기화는 하지 않았습니다. Mac의 무선 디버깅 연결도 종료합니다.

기존 주 1회 Mac 서명 갱신의 커밋 소스도 빌드 45에 맞춥니다. 갱신을 지금 실행하지 않으며, 워치 인터넷만의 무료 자동 서명 목표는 별도 미완료 항목입니다.
