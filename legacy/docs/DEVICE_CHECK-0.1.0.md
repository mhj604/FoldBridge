# 실제 기기 확인

아직 완료하지 않은 검증입니다. Mac의 Xcode 빌드부터 시작하세요. 소프트웨어 검사 통과만으로 지연이나 폴드7 호환성을 확정하지 않습니다.

## 필요한 정보

- 갤럭시 모델, Android와 One UI 버전
- 애플워치 모델과 watchOS 버전
- Xcode 버전
- BLE 기본 빌드 또는 Push 빌드
- 테스트 당시 워치의 Wi-Fi 또는 셀룰러 연결 상태

## 순서

1. Mac에서 `python3 watch/build_watch.py`로 watchOS 시뮬레이터 컴파일을 확인합니다. 오류가 있으면 첫 오류와 주변 로그를 보존합니다.
2. Xcode에서 실제 워치를 대상으로 설치합니다. 시뮬레이터는 실제 BLE 성능을 검증하지 못합니다.
3. 양쪽 앱을 켜고 새 기기 등록을 진행합니다. 두 기기의 코드를 비교합니다.
4. 테스트 알림 한 개를 보내고 워치의 표시와 Android의 수신 확인을 함께 확인합니다.
5. 카톡 등 전달할 앱 하나를 선택하고 다른 사람이 보낸 메시지 20개를 한 개씩 보냅니다. 폰 화면이 켜진 경우와 꺼진 경우를 나눠 기록합니다.
6. 짧은 본문과 긴 한글 본문을 나눠 확인합니다. 같은 알림의 내용이 갱신될 때 중복 표시와 새 내용 수신을 확인합니다.
7. 워치 앱을 켜둔 상태에서 Android의 최근 전달 확인 시간 20개를 적고 중앙값과 95백분위수를 계산합니다. 이 값에는 메시지 확인 왕복이 포함됩니다.
8. 두 기기를 나란히 촬영해 실제 화면 표시와 진동의 차이도 따로 확인합니다. 소프트웨어의 수신 확인 수치와 물리적 표시 지연은 다릅니다.
9. 휴대폰 또는 워치의 Bluetooth를 껐다 켜고 워치 앱을 다시 엽니다. 2분 이내 보류 알림이 도착하는지 확인합니다. 과거 알림을 무한 재생하지 않도록 2분이 지난 알림은 버립니다.
10. 워치 앱을 닫고 반복합니다. BLE만으로 계속 받을 것으로 가정하지 마세요. Push 빌드와 서버를 설정한 경우에는 APNs 전달 경로를 별도로 확인합니다.
11. 워치가 Wi-Fi와 셀룰러를 모두 잃은 상태와 다시 연결된 상태를 확인합니다. 이 상태에서 즉시 Push 수신은 불가능합니다.
12. 갤럭시의 `연결 중지`와 기기 등록 해제가 새 전달을 중단하는지 확인합니다.
